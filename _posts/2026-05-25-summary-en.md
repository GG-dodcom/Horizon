## [C Extensions and Portability Across Compilers](https://lemon.rip/w/6-c-extensions-compilers/) ⭐️ 7.8/10

An article on lemon.rip discusses the challenges of C extension portability across different compilers, highlighting common practices like using __attribute__ and conditional compilation checks that often break on non-GCC/Clang compilers. This matters because C remains a foundational language in systems programming, and portability issues hinder code reuse and maintainability across platforms and compilers, especially for projects targeting diverse environments like Windows, FreeBSD, or embedded systems. The article points out that many C projects rely on GNU C extensions (e.g., __attribute__) and use preprocessor checks like #if !defined(__GNUC__) without also checking if the extension is already defined, causing failures on alternative compilers. Solutions include writing portable code that detects feature availability rather than compiler identity.

hackernews · xngbuilds · May 25, 14:15 · [Discussion](https://news.ycombinator.com/item?id=48267126)

**Background**: C extensions are non-standard features added by compilers like GCC and Clang to provide additional functionality, such as inline assembly, attributes, or built-in functions. The C standard only defines a baseline, and compilers often diverge in what they support. Portability libraries or conditional compilation with #ifdef are common workarounds, but they can become brittle when encountering compilers that don't fully mimic GCC.

Users may need to re-log to their Mullvad account before changing servers to regenerate WireGuard keys and internal addresses, which is part of the mitigation. Mullvad distributes users across many exit IPs per server to reduce congestion, but this created predictable patterns. The mitigation breaks those patterns by assigning unique IPs per session.
