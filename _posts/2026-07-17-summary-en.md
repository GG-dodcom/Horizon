## [Frame: Linux X Server in Assembly Generated by Claude LLM](https://isene.org/2026/07/Frame.html) ⭐️ 9.2/10

A project called Frame implements an X11 display server entirely in x86_64 assembly, totaling nearly 25,000 lines of code, and was generated using the Claude LLM. The author claims it has no dependencies on Mesa, FreeType, Xlib, or even libc, interfacing directly with Linux system calls and DRM/KMS interfaces. This project challenges traditional assumptions about the complexity of reimplementing X11, showing that LLMs can generate low-level systems code at scale. It also sparks debate about authorship and the role of AI in software engineering, potentially shifting how developers approach foundational system software. Frame is a single assembly file about 25,000 lines long, built from scratch with no existing X server code. It has been demonstrated running a live environment with dwm and alacritty, though the author notes window focusing issues. The entire codebase was generated by Claude, not manually written.

Writing an X server in assembly is an extremely complex task typically considered impractical. LLMs like Claude can generate assembly code from high-level descriptions, effectively acting as a compiler. This project leverages that capability to produce a functional, albeit minimal, X server.

This demonstrates the feasibility of running a full, complex browser inside another browser using WebAssembly, pushing the boundaries of browser-based virtualization. It also highlights the growing role of AI-assisted development in tackling massive porting projects. All network traffic is funneled through a WebSocket using the Wisp protocol via Puter's server, as browser code cannot open arbitrary network connections. The project supports end-to-end encryption; Simon Willison verified that HTTPS traffic remained encrypted while HTTP traffic was in cleartext.

**Background**: WebAssembly (WASM) is a binary instruction format that allows high-performance code (e.g., C/C++ compiled) to run in web browsers at near-native speed. Compiling a whole browser like Firefox into WASM is a massive undertaking, requiring significant engineering and AI-assisted refactoring. This project leverages LLMs to help port and optimize the Gecko engine's single-process support for the WASM target.
