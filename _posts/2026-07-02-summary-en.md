## [Linux 6.9 Bug Retains LUKS Encryption Keys in Memory](https://mathstodon.xyz/@iblech/116769502749142438) ⭐️ 8.0/10

A regression in Linux 6.9 causes the LUKS suspend operation to no longer wipe disk-encryption keys from kernel memory, undermining security guarantees of full-disk encryption. This flaw means that when a LUKS-encrypted system is suspended, the master key remains in memory, making it vulnerable to cold boot attacks or other memory extraction techniques. The luksSuspend command is meant to temporarily block I/O and wipe the encryption key from kernel memory; after Linux 6.9, the key eviction step is skipped, a test by NixOS identified the regression.

hackernews · IngoBlechschmid · Jul 2, 15:25 · [Discussion](https://news.ycombinator.com/item?id=48763035)

**Background**: LUKS (Linux Unified Key Setup) is the standard for full-disk encryption on Linux. When a system is suspended to RAM, the encryption key is normally kept in memory to allow resuming without re-entering the passphrase, but luksSuspend is used to explicitly wipe the key for security during suspend. The bug means this wipe no longer occurs.
