## [Rust project goals propose immobile types and guaranteed destructors](https://github.com/rust-lang/rust-project-goals/blob/main/src/2026/move-trait.md) ⭐️ 8.3/10

The Rust project has added a new project goal for 2026 proposing the addition of immobile types (!Move) and guaranteed destructors (!Forget) to the language. The proposal, published in the move-trait.md goal document, outlines how types can opt out of being moved or forgotten, addressing long-standing limitations. This proposal could fundamentally change how Rust handles self-referential types, async futures, and resource cleanup. If implemented, it may eventually deprecate the Pin workaround and enable safe scoped spawn, making Rust a better fit for systems programming. The project goal is a roadmap commitment, not a finalized language change, so the exact design may evolve. It introduces opt-out trait bounds like !Move and !Forget, with !Forget types having restricted usability, and also references a separate 'pinned places' proposal by withoutboats as an alternative design.

hackernews · paavohtl · Aug 3, 06:42 · [Discussion](https://news.ycombinator.com/item?id=49152023)

**Background**: Rust has historically assumed that all values can be moved in memory and forgotten via mem::forget without running destructors. This assumption breaks for self-referential types, which is why the Pin type was introduced as a workaround. The new goal aims to allow types to opt out of these capabilities, guaranteeing that destructors run and enabling patterns like scoped threads and linear types.

## [AirLLM runs 70B LLMs on a 4GB GPU via layer streaming](https://github.com/lyogavin/airllm) ⭐️ 7.7/10

AirLLM, an open-source GitHub project, now enables inference of 70B-class large language models on a single 4GB GPU using memory-efficient layer streaming. The project recently gained attention on Hacker News, with its v3.1.0 release benchmarking 292 seconds per token on the Kimi K3 model. This pushes the frontier of running very large models on consumer hardware, dramatically lowering the barrier for individuals and small teams to experiment with 70B-class models. It also sparks an important community debate about whether such layer-streaming tools offer real advantages over established approaches like llama.cpp with quantization and memory offloading. AirLLM streams transformer layers into VRAM on demand rather than loading the entire model, so it greatly reduces memory requirements but incurs very high latency — the v3.1.0 benchmark shows 292 seconds per token on a 48GB RTX 6000 Ada. The README notes that users still need to connect to HuggingFace, which suggests the full model may not need to be downloaded locally. Hacker News commenters question its differentiation from llama.cpp's -cmoe/-mmap flags and express concerns about long-term maintenance.

**Background**: Large language models typically require enormous GPU memory; for example, a 70B model in full precision needs roughly 140GB of VRAM. To run such models on limited hardware, developers have developed techniques like quantization (e.g., bitsandbytes FP4) and offloading, which stream layers between RAM, VRAM, and SSD. AirLLM is one of these memory-optimization projects, using layer-wise streaming to fit 70B models into a single 4GB GPU, trading speed for drastically reduced memory usage.
