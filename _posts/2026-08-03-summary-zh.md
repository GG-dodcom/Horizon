## [Rust 项目目标：不可移动类型与保证析构](https://github.com/rust-lang/rust-project-goals/blob/main/src/2026/move-trait.md) ⭐️ 8.3/10

Rust 项目新增了 2026 年项目目标，建议在语言中引入不可移动类型（!Move）和保证析构（!Forget）。目标文档 move-trait.md 描述了类型如何选择退出被移动或被遗忘的能力，以解决长期存在的局限。 该提案可能从根本上改变 Rust 处理自引用类型、异步 Future 和资源清理的方式。如果得以实现，它最终可能会取代 Pin 这一变通方案，并支持安全的 scoped spawn，使 Rust 更适合系统编程。 该项目目标只是路线图承诺，并非最终的语言变更，具体设计仍可能发展变化。它引入了 !Move 和 !Forget 这样的选择退出 trait 约束，其中 !Forget 类型的使用受到更多限制，同时还提到了 withoutboats 的 'pinned places' 提案作为另一种设计方案。

hackernews · paavohtl · Aug 3, 06:42 · [社区讨论](https://news.ycombinator.com/item?id=49152023)

**背景**: Rust 历来假定所有值都可以在内存中移动，并且可以通过 mem::forget 丢弃而不运行析构函数。这一假定对自引用类型不成立，因此引入了 Pin 类型作为变通方案。新目标旨在允许类型选择退出这些能力，保证析构函数一定运行，从而支持 scoped 线程和线性类型等模式。

## [LiteLLM v1.94.1 发布：支持用 cosign 验证 Docker 镜像签名](https://github.com/BerriAI/litellm/releases/tag/v1.94.1) ⭐️ 7.1/10

LiteLLM v1.94.1 的发布说明介绍了如何使用 cosign 验证其 Docker 镜像的签名，既可以固定 commit hash（推荐），也可以使用 release tag。该版本是一个补丁，将 PR #35277 回溯移植到 stable/1.94.x 分支。 这很重要，因为它为 LiteLLM 用户提供了一种实用的、有文档支持的供应链安全验证方法，适用于 LLM 网关部署。随着 AI 基础设施越来越多地投入生产环境，验证镜像签名有助于防止部署被篡改或恶意的镜像。 推荐的验证方法使用固定的 commit hash（0112e53），因为 commit hash 在密码学上是不可变的；便捷方法则使用 v1.94.1 tag，依赖仓库的 tag 保护规则。所有 LiteLLM Docker 镜像都使用该 commit 中引入的同一把 cosign 公钥签名，验证输出会确认 cosign claims 和公钥验证结果。

**背景**: Cosign 是 Sigstore 项目下的一个命令行工具，用于对容器镜像等软件制品进行签名和验证。它使用密钥对：公钥以 cosign.pub 的形式发布在仓库中，可通过 URL 获取，而签名在本地验证，无需信任镜像仓库。这种方法顺应了容器供应链安全的大趋势，通常还会与 Kyverno 等策略引擎集成，以自动执行验证。
