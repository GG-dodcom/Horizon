## [Vercel AI SDK patch adds SSRF protection via URL validation](https://github.com/vercel/ai/releases/tag/%40ai-sdk/xai%404.0.12) ⭐️ 8.5/10

The @ai-sdk/xai@4.0.12 patch release from Vercel introduces a `validateUrl` flag in `getFromApi` that enables URL validation to prevent Server-Side Request Forgery (SSRF) attacks, along with enhanced redirect handling and new `credentialedOrigin` and `trustedOrigin` options. This security fix is critical for developers using the AI SDK, as SSRF vulnerabilities can allow attackers to access internal systems and sensitive data via manipulation of provider response URLs. By validating URLs and restricting redirects, the update significantly reduces the attack surface in AI applications. The `validateUrl` flag is optional for backward compatibility, but all AI SDK provider packages now set it explicitly. When enabled, URLs are routed through `fetchWithValidatedRedirects`, which rejects private/loopback/link-local targets, validates redirect hops, and strips sensitive headers except user-agent on cross-origin redirects. Blocked URLs throw a `DownloadError`.

github · github-actions[bot] · Jul 13, 21:35

**Background**: SSRF (Server-Side Request Forgery) is an attack where an attacker tricks a server into making requests to internal or unauthorized resources, often bypassing firewalls. The AI SDK from Vercel provides provider utilities for integrating various AI models. This patch specifically addresses URL handling in `getFromApi`, a function used to fetch data from provider response bodies, which previously lacked validation against malicious URLs.

## [Markets competitive if and only if P != NP](https://feeds.feedblitz.com/~/960233768/0/marginalrevolution~Markets-are-competitive-if-and-only-if-P-NP.html) ⭐️ 7.5/10

A new blog post on Marginal Revolution proves that competitive market outcomes require computational intractability, specifically that markets are competitive if and only if P != NP. This result connects two fundamental concepts—computational complexity and market competition—suggesting that the very possibility of competitive markets hinges on an unresolved problem in computer science. The argument relies on the 'collusion detection problem': if P=NP, firms can efficiently detect deviations from collusive agreements, making collusion stable; if P!=NP, detection is infeasible for markets with 'instance-hardness'.

rss · Marginal Revolution · Jul 13, 06:55

**Background**: P vs NP is a central problem in computer science asking whether every problem whose solution can be verified quickly (NP) can also be solved quickly (P). Collusion detection in economics involves identifying when firms secretly coordinate to fix prices or reduce competition; it is typically considered a hard problem. The blog post formalizes this intuition by showing that if collusion detection becomes easy (P=NP), then collusion becomes sustainable, undermining competitive markets.
